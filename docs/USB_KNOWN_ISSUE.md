# USB 已知问题与保留记录

状态：**暂停排查，右侧 USB-C 可用，左侧 USB4 与 iPad 游戏前台的连接问题未解决。** 不作为游戏适配已经修复的成果。

## 环境和现象

Windows 笔记本 ASUS ROG Zephyrus G14 GA403WR，BIOS 310；Apple USB 驱动版本 538.0.0.0。右侧 USB-C 是支持 USB 3.2 Gen2 数据与 PD 的接口，并非只能充电，已短时验证游戏前台连接与应用文件读取。左侧是 USB4；本次没有测得实际协商数据速率，不能声称传输用了 40 Gbps。

左侧有时连充电标志都没有，电脑完全不枚举设备；物理断电/EC 重置后可恢复，一旦游戏前台又出现消失。故障后同一左口仍能连接 USB-C→Lightning 的 iPhone，但这并不是同一条 USB-C 双头线的数据/PD 路径。iPad 用同线接墙充正常。

文件资源管理器可见照片/DCIM 只代表相机传输接口被识别，不等于游戏文档服务或所有配对通道都正常。iPad 通常也不是可随便写 App 文件的普通移动硬盘。

## 已做及结论边界

- 发现 AppleUsbFilter 驱动加载失败事件，以及不同层使用 Apple / 其他已有驱动包的情况。对相关父设备做过官方 Apple 绑定，并保留原有驱动包与备份。混合绑定不是已证明的唯一根因。
- 重启过 Apple Mobile Device Service 并扫描设备；重启 UCSI 管理设备、左侧 xHCI 一次。命令成功不等于端口实际恢复。
- 观察到过 UCSI AckCcCi 超时，驱动改动前后均有。用户确认关机后持续按电源约 20–40 秒，确实尝试过物理 EC 重置。
- 左口恢复读取后，游戏打开再次失联；新故障未同时产生新的相同驱动/UCSI 事件。
- 关闭游戏模式未自动恢复；后台、原口重新插线、电脑端插头翻面、接电脑电源等未稳定解决。
- 只读 hub 查询当时报告 `NoDeviceConnected`，不是其接口上报过流状态；这不足以排除 USB-C 协商/供电控制固件异常。
- 没有电压、电流、PD 协商的实测。游戏功耗大于端口供电时，正常设计可由电池补足，并不必然要求断开数据；用户提出的保护/供电假设仍未证实。

没有卸载用户原有 iOSRealRun，也没有删除其驱动包或测试其后续虚拟定位功能。没有刷 BIOS 或安装 retimer 更新；厂商通用性能说明不能当成本故障修复保证。原始设备事件、机器路径、驱动备份与配对信息留在私有工作区，公开档案只保存脱敏结论。

继续开发时先用已验证的右口。若日后再查左口，先比较同一 iPad、同一 USB-C 数据线、游戏关闭/打开时的 PnP 和 USB-C/PD 状态，并避免同时修改游戏和驱动。无需为当前归档再做任何设备操作。
