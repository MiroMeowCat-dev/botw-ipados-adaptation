# 恢复、升级和备份

## 哪些必须私人保留

| 文件/内容 | 日常升级 | 全新恢复 |
| --- | --- | --- |
| 本仓库源码与纯模块 | 用于改适配、重编与核对 | 只能恢复适配层 |
| 固定 v9 无签名 Documents 主体 | 当前公开打包工具的直接输入 | 可重装主体，但含游戏成分，私人保存 |
| 最近可用 v10 主体/回退输入 | 续签及出错回退 | 重装主体 |
| 主 RomFS / 着色器 / DLC 与完整来源备份 | 一般无需重传 | 必需；公开仓库没有这些内容 |
| 存档/偏好 | 更新前备份 | 恢复游戏进度和布局 |
| 自己的签名资格/账号 | 安装时获得有效签名 | 不要将账号或私钥放在 GitHub |

电脑可以清理重复游戏文件，只要移动硬盘的来源与恢复包可靠且实际可读；公开归档不能代替外部游戏备份。建议同时保存当前 v9/v10 无签名主体和资源哈希，防止只有 Mac `.app` 而丢失固定 iOS 宿主。单独原始 Switch ROM 不等于当前已适配好的宿主。

## 普通覆盖更新

1. 游戏内保存，然后从多任务彻底退出。备份本游戏的存档和偏好。
2. 用 `tools/apply_update.py` 对固定原始 v9 输入应用纯模块。输入 SHA 固定，不提供强制跳过；脚本只离线读写本地文件。
3. 用 iLoader 或自己的有效开发签名途径处理新私人 IPA；本次成功配置需要 increased-memory-limit 与扩展虚拟地址权限，同时核对描述文件和实际签名。
4. 使用给既有游戏签名的相同账号/Team 与最终应用标识覆盖安装。先确认工具是否会自动追加 Team 后缀，避免形成新应用。**不要先卸载原 App。**
5. 核对 Documents 资源与存档，启动同一存档，验证菜单、触控、体感。设置中标注需重开的项目要彻底退出再开。

同身份覆盖更新保留文档数据，因此本次更新无需重传约 15 GB 主镜像和着色器；应用主体本身仍约 1.51 GB，安装工具可能重新上传整个主体，并非只有几百 KB 的差分传输。

纯模块必须通过自己的有效签名整合到宿主中，不能直接扔进 iPad 文件 App 里生效。免费开发签名有到期续签要求；这个更新方案没有永久签名功能，不取消开发者模式要求。

## 全新安装或意外卸载

卸载通常会删除该应用容器，届时要重新安装主体、导入主数据与着色器，再恢复私人存档。除非确认备份完整，否则不要把卸载当成更新故障的第一解决方法。外部来源数据建议先做哈希核对，再按上游 Documents/seed 格式导入。

本仓库没有通用从零游戏生成器，也不提供资源转储/解密密钥。完整历史大包/ZIP64 实验未纳入自动安装器；此前失败整包不是推荐恢复入口。

## 构建工具的适用范围

`build_overlays.py` 使用固定宿主 SHA 和 `compat/` 防误调用信息，编译三个模块并做静态分析，输出独立的重编 kit。它不会因换了一个新宿主就自动推导正确 ABI；宿主更新时需重新审查函数和全局变量，再完成设备验证。

`apply_update.py` 只接受清单固定 v9 无签名 IPA；从 v10 签名 IPA 再更新、从 Mac App 转换、原始完整 17 GB IPA 转分体均不在该新脚本范围内。历史流程见 PROCESS。输出是需要重新签名的私人候选，文件名/时间戳差异可使其哈希不同于已安装历史包；运行模块与设置内容受清单约束。

本地输出必须置于公开仓库外；审计工具拒绝游戏、签名材料和未列入白名单的文件。不要把私人输入、输出、日志临时复制到仓库里再指望 `.gitignore` 解决已经上传的内容。
