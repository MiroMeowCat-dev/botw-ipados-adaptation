# 成功的适配过程

## 1. 确认实际输入，选择已有 iOS 宿主

最初讨论过 nxnative、模拟器、逆向工具和系统虚拟化。最终 BotW 路线来自用户提供的本地整合包；检查发现里面已经有 ARM64 iOS/iPadOS IPA，并非只有 macOS 程序。包内目录叫 `TOTK.app`，实际游戏是 BotW 1.6.0，不能根据这个内部目录名认定为《王国之泪》。宿主链接 UIKit、Metal、GameController，最低版本 iOS 26。

其基础属于 Switch ARM64 二进制适配路线：在 Apple ARM64 平台运行游戏逻辑，宿主实现原平台服务与图形接口兼容，图形通过 Metal 呈现。我们复用了已有宿主、游戏适配及预编译着色器，并没有实现整套 Switch OS，也没有把 macOS 客体装入 iPad。nxnative 与这条路线有技术渊源，但本次成功 BotW 的直接基础是 MacNativeGames。MelonNX 属于备选模拟器；「逆向一切」没有成为成功构建的必要工具。

## 2. 校验并恢复资源

初始 IPA 约 17.52 GB；主 RomFS 为 15,131,979,952 字节。DLC1 原条目的 CRC / 哈希异常，从用户自己的 Mac App 备份恢复正确副本；DLC1 为 1,390,370,680 字节，另一 DLC 条目为 648 字节。恢复后重新检查主数据、两个 DLC 的哈希和整包 CRC。

原包拥有约 8.4 万文件和约 2.1 万份预编译 Metal 库。这些均未纳入公开仓库。Windows Metal 工具在此前别的构建路线准备过，不能将本次 BotW 成功归因为重新编译全部游戏着色器。

## 3. 分离连接、解包与权限问题

早期 Sideloadly 0.72 过程遇到 USB 消失与 `PackageExtractionFailed`，两者不是同一问题。小包对照确认一种 ZIP64 本地头与目录尺寸声明不一致的组合会引发设备拒绝解包。修正该文件头后，实际完整游戏仍未成功安装，所以不能宣称已经查清大包失败的所有根因，也不能简单说 iPad 不支持 ZIP64 或大于 4 GB 文件。

最终使用宿主已有的 **Documents 数据布局** 绕开超大整包安装：主体约 1.51 GB，主镜像与着色器作为应用文档另传。主体仍包含运行程序、DLC 和其他资源，不能公开当作“无游戏更新”。

## 4. 安装主体，导入文档资源

用户完成电脑信任、开发者模式、重启及开发者信任。利用 Apple 设备服务和 pymobiledevice3 上传与核对：

```text
私有宿主 IPA --签名/覆盖安装--> iPad 应用
私有主镜像 --拆分/传输--> Documents/GameData/romfs.bin.000 … .014
私有着色器 --既有种子导入流程--> Documents 下的 shader seed
存档/偏好 --更新前备份，更新后比较--> 同一应用容器
```

主镜像拆为 15 片，每片最多 1 GiB。原有种子传输使用 TOTKPACK1 布局；应用再按原有导入流程处理。保留并核对 `romfs.sha256` 和 `shader-seed.txt`。

完整主镜像 SHA-256：
`89d922b7b01f09766530a601f3dcfca8bdd4e94e6387f1c1335c4f3c6662b625`

着色器种子指纹：
`4ca3acad135a3d59e14a5a15effd4050069ea8909f1c759715d6a0276677d72b`

这些是数据一致性标识，不含数据，也不是解密密钥。

## 5. 解决运行内存权限

最初出现“编译着色器后闪退”，检查签名/描述文件后转向内存权限。GetMoreRAM 原版、社区登录修复及几轮网络兼容尝试经历 -80045、3840、-1001、HTTP 503，未完成这条路线。它不是最终必需软件，也不应反复让用户输入密码试错。

改用上游正式发行的第三方工具 iLoader 2.4.1，用户本人登录自己的 Apple 账号，保留相同 App ID / Team 的身份，申请并签入 `com.apple.developer.kernel.increased-memory-limit` 及扩展虚拟地址权限，实际核对签名与描述文件。只在文件中写 entitlement 不等于 Apple 已授权。完成后真机进入场景并控制林克。

后续已有合法本地签名材料的同身份更新使用 rcodesign 与 Apple 安装服务；个人证书、私钥、描述文件、账号和配对记录全部留在私有工作区。Apple 官方 Xcode 可管理开发签名，但本次完成路线在 Windows 上进行，没有使用 Mac。

## 6. 编译 iPad 适配层并迭代

使用 Windows Clang/LLD + 自备 iPhoneOS SDK 编译自有 Objective-C/C 适配模块，在本地宿主中追加相应动态库加载项。早期仅对固定启动器的一个 `setenv` overwrite 标志进行已校验修补，允许启动前偏好选择 docked 模式；并非重编游戏代码。最终 v10 主程序与 v9 完全相同。

先添加显示档位和性能可观测性，再处理触控、全屏、背包兼容、体感、限帧和统一设置。每次覆盖更新前保存退出、备份存档，检查资源与身份；后续只更换主体，不重传 15 GB 主数据和着色器。

## 7. 最终保存

公开部分包括最终源文件、固定宿主 ABI 防误用信息、纯自有模块和可移植构建/打包工具。本地旧脚本绑定个人路径、签名流程和逐版输入，未直接整体公开。当前公开工具从固定 v9 私有输入重建最终 v10 更新；不是能重放所有早期试验的完整流水线。此前 v7–v9 的关键差异已保存在版本说明中，完整游戏恢复仍依赖用户自己的外部备份。
